# 詮栩 CNC 雲端系統

單人使用的 CNC 雲端工具入口。首頁提供「加工管理系統、庫存管理系統、資料備份／還原」三個功能；加工管理系統包含總覽、加工數量登記、加工數量查詢、訂單完工預估、基礎資料設定與資料匯出／刪除分頁。

前端使用 React、TypeScript 與 Vite，雲端資料使用 Supabase Free，可由 GitHub Pages 自動部署。管理員使用指定的 Supabase 帳號登入；訪客可免登入唯讀查看資料，但無法新增、修改、刪除、盤點、匯出或還原。刪除、完整備份與還原會再要求一次管理員帳號密碼。專案不含 Lovable 套件、執行環境或任何平台綁定。

## 已完成功能

- 深色細格線介面、桌面側欄與手機版選單
- 全站數字欄位隱藏輸入框右側的上下箭頭，數值可直接輸入。游標在已選取的數字欄位上捲動時，欄位會離開焦點，頁面或視窗仍可照常捲動。
- 加工與庫存的表格頁面提供快速捲動按鈕。手機版捲動時右下角會顯示回頁首及到頁尾的按鈕，停止捲動約 1.8 秒後自動淡出。按下箭頭時會重新計時，方便點按。
- 電腦版的加工數量登記與查詢採較短的欄位與區塊間距。出入庫登記及新增品項視窗在手機與電腦上都縮短上下留白，維持原字級。
- 出入庫登記的主標題及欄位名稱跟隨按鈕配色，入庫為青綠色，出庫為橘紅色。新增品項使用各欄位的獨立配色，可輸入與選取的內容維持白色。
- 手機與電腦版的「登記出庫」「登記入庫」及「新增品項」表單使用左側標題、右側輸入，每個欄位獨占一列，列間距統一為 10 px。現行樣式的欄位標題、輸入值及下拉選項皆為 16 px。
- 「新增品項」依序顯示編號、條碼、品名、分類。編號由系統在儲存時產生，尚未組合出品名時品名欄顯示「自動組合」。欄位標題省略星號，條碼、斷屑槽、單價及備註可留空，其餘顯示的可輸入欄位必填。期初數量可以明確填 0。尺寸及材質只在需要它們的分類顯示。
- 編號、條碼及品名的配色可在 `src/styles.css` 的 `.product-create-modal` 調整，`--product-identity-label-color` 控制標題與條碼聚焦邊框，`--product-identity-border-color` 控制一般輸入框邊框。
- 「編輯刀具」沿用「新增品項」的欄位順序、左側標題、右側輸入與 10 px 列距。編輯欄位標題、編號／條碼／品名的邊框及儲存按鈕採紫色，配色集中在 `src/styles.css` 的 `.product-edit-modal`。
- 系統首頁：加工管理系統、庫存管理系統與資料備份／還原三個功能入口。「登出」或「返回登入」位於「功能選擇」右側。
- 加工管理系統使用獨立側邊分頁；基礎資料設定可新增或刪除產品編號與機台，也可編輯產品編號並同步取代全部既有加工紀錄中的舊編號
- 刪除選單項目只會停止新登記使用，既有加工紀錄仍會保留並可從查詢頁查看
- 加工數量登記：日期、產品編號、機台、時數、分鐘及數量必填，備註選填。時數或分鐘沒有數值時可填 0，合計須大於 0。產品編號和機台只能從已建立的下拉選單選擇。手機版各欄位的標題靠左、輸入靠右，標題 18 px、內容 20 px。電腦版與手機版的工時區同列依序顯示「加工時間」、時數輸入框、「時」、分鐘輸入框、「分」，實際總時間另列於下方。工時欄位可手動輸入最多兩位數，分鐘滿 60 自動進位。手機版按 Enter 可從時數接續到分鐘與數量。
- 若已有相同加工日期、產品編號和機台的登記，無論原登記是何時建立，送出時都會顯示最近建立的相符紀錄和本次填寫內容，可選擇覆蓋原登記、新增一筆或取消。
- 登記頁以彈出視窗提供工時相減，例如 `11 小時 5 分 - 3 小時 10 分 = 7 小時 55 分`，並可把結果帶回實際工時
- 加工數量查詢：選擇產品編號後，可查日期區間、全部紀錄或最後一筆。「查詢最後一筆」會列出產品最新加工日的所有機台，並加總當天的數量與時間。產品編號留空時，會列出所有有加工紀錄的產品，各自顯示最新加工日的明細和合計。「查詢最後一筆」使用完整歷史紀錄。
- 管理員可在加工數量查詢的結果按「編輯」調整該筆紀錄。手機與電腦版的編輯表單沿用加工數量登記的左標題、右輸入排列。日期、產品編號及機台之後是加工時間，時數與分鐘同列，總時間顯示在下方，再接數量、備註及「儲存修改」。
- 三種加工查詢結果都可逐筆刪除；刪除後列表與統計會立即重算
- 加工統計：「查詢最後一筆」將總時間、1 顆平均和總數量排在同一列，並在總數量上方顯示產品編號。查詢全部、日期查詢及資料匯出與刪除的預覽另顯示總天數與每日平均顆數。
- 「查詢全部」會在產品合計下方列出各機台的加工天數、總時間、每日平均、每顆平均時間及總數量。每台機台以自己的實際加工日期計算天數。電腦版使用表格，手機版每台機台各有一張卡片。
- 訂單完工預估的「歷史產能依據」可使用全部紀錄或指定日期區間，不再另外選擇歷史樣本、正常工時或加班方式
- 預計使用機台數只接受整數；系統優先採用歷史中實際使用相同機台數的加工日平均產量，沒有相同機台數的日期時才依每台平均產量換算，因此畫面的平均產量會與預估日產量一致
- 訂單剩餘數量固定以「訂單總數量－全部歷史累計完成量」計算，不會因歷史產能日期區間而改變
- 所選歷史產能資料只要包含星期六紀錄，未來排程就會自動計入星期六；沒有星期六紀錄時只排星期一至星期五，不再判斷是否加班
- 預估結果顯示剩餘數量、預估日產量、所需加工日與預計完工日期；星期日、國定假日與補假不列入加工日
- 訂單交期會評估交期前可加工日數，以及是否能完成、可多完成或尚缺多少數量
- 訂單完工預估會在目前瀏覽器保存所選產品、訂單數量、訂單交期、歷史範圍、日期區間與機台數；切換功能或重新整理後會自動還原（草稿不會跨手機與電腦同步）
- 國定假日資料集中在 `src/lib/taiwanHolidays.ts`；官方公布新年度辦公日曆後需將新年度日期加入此檔案
- 資料匯出與刪除使用同一個側邊分頁；選擇產品編號後會直接顯示全部加工紀錄與統計，可選擇下載 Excel 或永久刪除
- Excel 下載會輸出真正的 `.xlsx` 活頁簿；工作表、欄位、欄寬與底部統計列依提供的範例格式製作
- 永久刪除會把加工紀錄與「管理產品編號」中的選項在同一交易內一起刪除，並再次要求管理員密碼
- 登記頁可刪除最後一筆加工紀錄
- 庫存總覽：庫存總數、估算價值、本月入庫/出庫、近 14 天圖表
- 庫存盤點：「實際數量」預設空白，更新成功後清空。請輸入現場數量，盤點到零時輸入 `0`。表格與掃碼盤點的數量欄支援手機數字鍵盤與滑鼠捲頁。有數量差異時，站內確認窗會顯示目前庫存、盤點後庫存及差異。確認後才更新，取消可保留輸入的數量與備註。系統保留原單價並以差異建立盤點調整紀錄。
- 「掃碼盤點」的實際數量和盤點備註採左側標題、右側輸入。視窗主標題、欄位標題及輸入框邊框的顏色可在 `src/styles.css` 搜尋 `--barcode-stocktake-title-color` 自訂。
- 庫存盤點表格最右欄依序顯示「更新」、「備註」與「查看」。點「備註」可先填寫這一筆的盤點備註，按「更新」完成有數量差異的盤點時一併寫入紀錄。點「查看」可查刀具備註、出入庫、購入、盤點、個別單價與金額，以及已記錄的欄位修改前後值和出入庫刪除紀錄。修改資料讀取既有的操作紀錄，範圍從這筆刀具建立後開始。
- 每次盤點更新會在出入庫紀錄的盤點備註中自動加入台灣日期與時間，並保留使用者輸入的備註
- 出入庫紀錄中的期初庫存統一顯示為「建立時初庫存」，並顯示該筆資料實際建立的台灣日期與時分。手機版備註與時間同列，過長可左右滑動。電腦版時間顯示於備註下方。既有的舊文字資料也相容。
- 盤點頁可新增沒有價格的新刀具，也能搜尋、分類篩選並逐項更新數量
- 刀具資料：搜尋、四種分類篩選、新增、編輯、刪除
- 刀具資料表依最後更新時間由新到舊排列。編輯刀具、綁定條碼或變更庫存後，最近更新的刀具會排到目前篩選結果最上方。
- 刀具資料的購入日期會顯示對應入庫紀錄的台灣時分秒；電腦版日期與時間上下排列，手機版將「購入日期」標題置左、日期時間同行緊接於右側，若沒有入庫紀錄則使用刀具資料建立時間
- 手機條碼掃描：可使用 iPhone 相機或 XB-6208-RB 藍牙掃描器辨識一維／二維條碼；掃描中、成功、未綁定會顯示不同顏色與明確提示，成功時播放提示音並自動移到結果
- 新增或編輯刀具時可自動產生不重複的 13 位內部條碼，並立即顯示相同內容的 QR Code 預覽；仍可保留掃描或手動輸入方式
- 「掃描刀具條碼」視窗提供 XB-6208-RB 的 iOS 鍵盤顯示／隱藏設定 QR Code，不必另外尋找紙本說明書
- 庫存管理導覽列的「掃描槍設定」提供 XB-6208-RB 的藍牙配對、休眠時間與聲音設定。選擇項目後，以掃描槍掃描畫面上的 QR Code。配對時依序掃配對碼 I、II，再從手機藍牙設定選擇 R&B40，或插上 USB 接收器。
- 新增商品先選「刀片、鑽銑刀、刀柄、其他」，表單依分類顯示需要的欄位
- 規格、尺寸、斷屑槽、材質、廠牌、供應商與單位都可輸入或從下拉選單選取。選項由現有刀具資料自動整理。輸入找不到相符選項時，清單會收起並保留輸入內容。
- 刀片品名依「規格－尺寸－斷屑槽－材質」組合；鑽銑刀依「規格－尺寸－材質」組合；刀柄與其他直接使用規格
- 商品編號依分類獨立編排：刀片 `T0001`、鑽銑刀 `M0001`、刀柄 `H0001`、其他 `O0001`
- 新增商品時可同時建立第一筆入庫
- 新增商品及入庫表單會依數量與單價即時計算採購總價
- 商品列可直接入庫、出庫，並顯示最新單價相對前次的漲跌百分比
- 歷史價格視窗：最新、最低、最高，以及每次入庫的日期、單價、價差、數量和供應商
- 出入庫商品可輸入編號、品名、廠牌、供應商或分類即時搜尋
- 一般入出庫的商品欄預設留空；從商品列快捷操作時才會自動選中該商品
- 入庫供應商會帶入商品目前的供應商，並支援從所有既有供應商下拉選擇或輸入新資料
- 每筆出入庫紀錄均可安全刪除；系統會重算後續餘額、商品庫存和最新單價，並拒絕會造成歷史負庫存的刪除
- 出入庫歷史：可掃描或輸入刀具條碼搜尋，也可依編號、品名、廠牌、供應商、備註、類型與日期區間篩選
- 出入庫、庫存盤點、刀具資料與刀具選擇搜尋可省略品名中的半形連字號 `-`。例如輸入 `WNMG080408NGE` 可找到 `WNMG080408N-GE`。
- 掃到尚未綁定的刀具條碼時，點「綁定現有刀具」可在同一視窗切換到搜尋清單。選擇刀具後鍵盤會收起，再按「確認綁定」。刀具已有不同條碼時，會顯示與加工數量登記的重複提醒同風格的確認視窗，暖橘卡片顯示原條碼，青綠卡片顯示新條碼。按「確認覆蓋」才會更新；取消會回到綁定畫面並保留選取的刀具。返回時會保留掃描結果。
- 編輯刀具時，按「重新產生條碼」會先確認。也可按旁邊的「重新掃碼」，開啟相機後選「使用此條碼」，將結果帶回表單；已綁定其他刀具的條碼無法選用。原先填寫的其他欄位會保留，按「儲存」後才更新刀具。
- 從「以此條碼建立新刀具」進入新增表單後，儲存成功會自動返回條碼掃描，顯示已儲存條碼的結果。儲存前也可按「返回條碼掃描」回到原掃描結果。
- 出入庫、庫存盤點與刀具資料的搜尋框支援連續掃描；掃描器送出 Enter 後會提示成功或失敗，1.8 秒後只清空可輸入文字並重新聚焦，上一筆搜尋結果會保留，下一次掃描會直接取代上一筆條碼
- 在條碼掃描結果按「盤點」，可在同一視窗輸入實際數量、備註並確認更新。完成後回到掃描結果，並帶到「掃描下一筆」按鈕。取消確認會返回表單，按「返回掃描結果」可以取消這次盤點。
- 從條碼掃描結果開啟「編輯刀具」「登記出庫」或「登記入庫」後，按右上角 X 會回到原條碼的掃描結果。
- 手機版出入庫、庫存盤點與刀具資料的搜尋及分類篩選使用可縮小的單欄網格，搜尋框與原生下拉選單會限制在篩選卡寬度內，避免實體 iPhone 右側溢出
- 手機版整個庫存管理系統的日期輸入框都會跟隨父層寬度縮放，包含出入庫日期篩選、入庫／出庫日期及新增刀具購入日期；iPhone Chrome／Safari 的原生日期元件不會再向右超出畫面
- 手機版彈出視窗會從畫面上方開始顯示，並依鍵盤出現後的可見畫面高度縮短；底部欄位可在彈窗內上下捲動，不再被手機鍵盤長時間遮住
- 庫存盤點表格依刀具資料的最後更新時間由新到舊排列；完成盤點、出入庫或編輯後，最近更新的刀具會排在較上方
- 側邊選單右上角的 X 是手機版關閉選單按鈕，只會在 620px 以下的手機側邊選單顯示；621px 以上電腦版會保持隱藏，不會被共用 icon-button 樣式重新顯示
- 入庫與出庫彈窗、負庫存提示、重複送出防護
- 自訂登入名稱 `kuanlin`，實際身分由 Supabase Auth Email／密碼安全驗證
- 登入名稱欄位只接受英文字母與數字，並關閉手機鍵盤的自動大寫、拼字修正與拼字檢查
- 登入畫面提供「訪客查看」；訪客可讀取正式雲端資料，但所有寫入功能與資料匯出均停用
- RLS 與安全交易 RPC 固定綁定單一 Supabase UID；匿名訪客只有四張業務資料表的 SELECT 權限
- 登入狀態只保留在目前瀏覽器分頁；重新整理不會中斷，關閉分頁或瀏覽器後需要重新登入
- 原子化 PostgreSQL RPC：鎖定刀具資料列，同一交易更新庫存與歷史
- 首頁可由管理員將完整 Supabase 資料匯出為 Excel，整理後經格式檢查再整批還原；備份檔另含可直接列印的「QR Code 標籤」工作表
- 無 Supabase 設定時自動使用可操作的瀏覽器示範資料
- GitHub Actions / Pages 部署設定

## 操作紀錄

管理員登入後，從首頁「功能選擇」開啟「操作紀錄」。庫存、加工異動與登入登出依台灣時間由新到舊放在同一張清單。每筆直接顯示操作者、操作內容與變更前後值。點開可看新增與刪除的完整業務欄位，或登入登出的驗證事件編號。

已啟用單一管理員模式的 Supabase 專案，先備份資料，再從 SQL Editor 執行 [`supabase/enable-operation-log.sql`](supabase/enable-operation-log.sql)。啟用後才會記錄刀具、出入庫、加工紀錄與加工選項的異動。使用新版網站執行 Excel 整批還原時，紀錄會顯示還原筆數。操作紀錄由資料庫寫入，只開放指定管理員查閱。

登入登出需接著執行 [`supabase/enable-operation-log-auth.sql`](supabase/enable-operation-log-auth.sql)，並在 Supabase Dashboard 的 **Authentication → Configuration → Audit Logs** 開啟 **Write audit logs to the database**。網站讀取資料庫已存留的管理員登入登出事件。若之前未開啟資料庫儲存，先前只留在 Supabase 後台的事件不會回填到網站。關閉網頁分頁本身不會產生登出事件。

## 測試模式

從功能選擇頁進入加工或庫存管理，再從導覽列底部選擇「進入測試模式」。訪客與管理員均可使用。測試模式載入獨立的範例資料，可練習加工登記、庫存出入庫、盤點、刀具與基礎資料管理。新增、修改、刪除及完工預估草稿只保存在目前分頁，重新整理或離開後在同一分頁再進入仍可繼續。

測試畫面使用暖色主題，並在全站顯示測試提示。測試模式停用 Supabase 連線及即時同步。雲端完整備份／還原、操作紀錄及通行密鑰設定須回到雲端模式使用。測試資料的刪除仍會要求確認。從導覽列底部或提示列按「離開測試模式」，即可回到原先的登入、訪客或系統首頁，實際畫面依目前的登入狀態決定。

## 連接 Supabase Free

### 1. 建立資料表、RLS 與安全交易函式

1. 在 [Supabase](https://supabase.com/) 建立專案。
2. 進入專案的 SQL Editor。
3. 開啟 [`supabase/schema.sql`](supabase/schema.sql)，複製整份內容並執行。

`schema.sql` 是建立空白專案基礎資料表使用。已經升級為單一帳號安全模式後，不要再次執行舊的 `schema.sql` 或 `admin_data.sql`，以免恢復舊共用政策。

這份 SQL 會建立：

- `products` 刀具表
- `stock_movements` 不可由前端直接竄改的出入庫歷史
- `production_records` 加工數量、機台、工時與備註紀錄
- `production_options` 產品編號與機台下拉選單資料
- 入庫紀錄同時作為刀具的歷史價格來源，不需另一張價格表
- 基礎 Row Level Security policies（最後會由單一帳號安全升級檔取代）
- `create_product_with_initial_stock(...)` 安全建立刀具 RPC
- `register_stock_movement(...)` 安全出入庫 RPC
- `delete_stock_movement(...)` 安全刪除與完整庫存軌跡重算 RPC
- `set_stocktake_quantity(...)` 鎖定刀具並以實際盤點數量建立差異紀錄的 RPC；不要求或覆寫單價
- `delete_production_product_data(...)` 原子化永久刪除加工紀錄與產品編號選項 RPC

`register_stock_movement` 會鎖定刀具資料列、檢查共用資料範圍與負庫存，並以 `request_key` 防止同一次請求重送造成重複加減。

### 2. 新專案先啟用完整 Excel 備份／還原

只有全新空白 Supabase 專案才需要先執行 [`supabase/admin_data.sql`](supabase/admin_data.sql)。不要再設定舊的 8 位數管理密碼；下一步安全升級會移除舊密碼表，改用 Supabase 帳號密碼重新驗證。

首頁的「資料備份／還原」可以：

- 匯出刀具資料、出入庫歷史、加工數量與管理選項到同一份 Excel。
- 自動建立「QR Code 標籤」工作表，以兩欄標籤排版已綁定條碼的刀具；QR Code 內容與「刀具資料」的條碼文字相同。
- 選擇整理後的 Excel，先檢查欄位、日期、數字、重複編號與資料筆數。
- 輸入「覆蓋資料」並再次通過帳號登入密碼後，以單一資料庫交易完整還原；發生錯誤會全部回復。

匯入會取代目前的雲端資料，務必保留一份未修改的原始備份。

### 3. 執行單一帳號安全升級

1. 先從舊網站下載一份完整 Excel 備份。
2. 確認 Supabase Authentication → Users 中已存在 `kuanlin@chyuansheu.com`，UID 為 `5568706d-caaa-459b-b842-13cdbc3929fc`。
3. 在 SQL Editor 建立 **New query**，完整貼上 [`supabase/secure_single_user.sql`](supabase/secure_single_user.sql) 後按 **Run**。
4. 成功畫面會顯示 `Success. No rows returned`。此檔會核對 UID 與 Email、把既有共用資料歸戶、關閉匿名寫入權限並重建安全 RPC。

安全升級完成後，不要再執行 `schema.sql`、`admin_data.sql` 或舊的 `set_admin_password` 指令。

### 3.1 啟用訪客唯讀資料

在 SQL Editor 建立 **New query**，完整貼上 [`supabase/enable-guest-readonly.sql`](supabase/enable-guest-readonly.sql) 後按 **Run**。

這份 SQL 只授予 `anon` 角色以下權限：

- 讀取 `products`
- 讀取 `stock_movements`
- 讀取 `production_records`
- 讀取 `production_options`

訪客沒有 INSERT、UPDATE、DELETE 或 RPC 執行權限。由於訪客不需要身分驗證，任何取得網站網址或 Supabase 公開端點的人都可能讀到這四張資料表；請勿存放不適合公開查看的個人或機密內容。

### 3.2 啟用加工產品編號編輯

在 SQL Editor 建立 **New query**，完整貼上 [`supabase/enable-production-product-code-edit.sql`](supabase/enable-production-product-code-edit.sql) 後按 **Run**。

這份 SQL 會建立只有指定管理員帳號能執行的安全 RPC。從「加工管理系統 → 基礎資料設定 → 管理產品編號」修改編號時，會在同一筆資料庫交易內同步更新產品編號選項與全部既有加工紀錄；若新編號已存在則會拒絕修改，避免兩個產品的資料意外合併。

### 啟用刀具條碼掃描資料欄位

在 SQL Editor 建立 **New query**，完整貼上 [`supabase/enable-product-barcodes.sql`](supabase/enable-product-barcodes.sql) 後按 **Run**。

這份 SQL 會新增刀具條碼欄位、避免同一條碼重複綁定，並把條碼加入完整 Excel 備份與還原。網站部署後，在庫存總覽、出入庫、庫存盤點或刀具資料頁按「掃描條碼」即可使用。iPhone 必須從正式 HTTPS 網址開啟，並允許 Chrome 使用相機。

新增或編輯刀具時的 QR Code 預覽使用隨主程式一併載入的 QR 套件，不再等使用者輸入條碼後才臨時下載獨立程式檔。這可避免桌面瀏覽器保留舊版快取、GitHub Pages 更新後舊 QR 動態檔案不存在而顯示「QR Code 產生失敗」。部署後若桌面仍顯示舊錯誤，請先按 `Ctrl + F5` 強制重新載入一次新版主程式。

### 4. 填入前端環境變數

從 Supabase 專案設定的 API 頁面取得 Project URL 與 anon/public key。如果需要在本機連線，在專案根目錄建立或編輯 `.env.local`，填入以下兩個變數：

```dotenv
VITE_SUPABASE_URL=https://你的專案.supabase.co
VITE_SUPABASE_ANON_KEY=你的_anon_key
```

重新執行 `npm run dev`。雲端模式會先顯示登入畫面；管理員登入名稱為 `kuanlin`，訪客可直接按「訪客查看」。

> `anon`／publishable key 本來就是供瀏覽器使用；絕對不要把 `service_role` key 放進 Vite、GitHub Pages 或任何 `VITE_` 變數。真正的資料保護由 Supabase Auth、RLS 與安全 RPC 負責。

首次使用或忘記密碼時，在登入畫面按「忘記密碼或尚未設定密碼」，輸入後台設定的管理員 Email；只有 Email 與系統管理員帳號完全相符時才會寄出重設郵件。請先在 Supabase Authentication → URL Configuration 將正式 GitHub Pages 網址加入 Redirect URLs。郵件連結回到網站後會顯示設定新密碼畫面；密碼限制為至少 6 位數字。

Supabase 專案本身也有密碼最短長度設定。請在 Auth 的 Password Security 設定中把 minimum password length 改成 `6`；否則前端與雲端的密碼規則可能不一致。

### 啟用通行密鑰登入（Face ID）

1. 到 Supabase Dashboard → Authentication → Passkeys，開啟 **Enable Passkey authentication**。
2. 以使用者實際開啟的 HTTPS 網址設定 WebAuthn。假設網址是 `https://your-account.github.io/cnc/`，Relying Party Display Name 可填「詮栩雲端系統」，Relying Party ID 填 `your-account.github.io`，Relying Party Origins 填 `https://your-account.github.io`。兩欄都不包含 `/cnc/`。
3. 部署新版後，用 iPhone 開啟正式網址，先用管理員帳密登入，進入加工管理或庫存管理系統並打開左側選單。在帳號下方、「登出系統」上方點「設定通行密鑰（Face ID）」，依裝置提示完成設定。
4. 登出後，點「使用通行密鑰登入（Face ID）」測試。iPhone 會依裝置設定提供 Face ID 或其他驗證方式，原有帳密也可繼續登入。

通行密鑰綁定 Relying Party ID，日後變更此設定須重新註冊。

登入頁會保留公司標誌、標題與原本直排的登入按鈕。點「帳號密碼登入」、「手機掃碼登入」或「忘記密碼或尚未設定密碼」，所需欄位或掃碼內容會直接展開在原頁按鈕上方。登入和寄送重設密碼郵件共用下方的主要按鈕。掃碼與重設密碼入口再按一次可收起，也可以直接改選其他方式。

登入頁依目前可見的視窗大小滿版顯示。手機將標誌、登入操作與頁尾直向分散，並在螢幕安全區之外保留內距。手機版正常內容在一頁顯示，展開欄位或開啟鍵盤後若空間不足，可以在登入頁內捲動。電腦左側顯示標誌與標題，右側是登入操作，頁尾置於下方。

登入頁使用 `public/icons/login-logo.png`，從參考原標誌比例的水平尾端金屬浮雕圖裁出 1010 × 845 像素透明圖檔。完整公司名由頁面文字呈現。標誌尺寸和登入按鈕的間距依手機與電腦視窗調整。

第一次點「帳號密碼登入」只會展開欄位，並在原位置改顯示獨立的「登入」按鈕。重設密碼在同一位置顯示青綠色寄信按鈕；「重新產生 QR Code」沿用掃碼入口的紫色。送出後的帳密驗證結果、通行密鑰錯誤、掃碼結果及重設密碼寄信提示，都顯示在登入標題與操作區之間。

### 啟用手機掃碼登入（不使用藍牙）

1. 確認 Supabase 專案正確後，在 SQL Editor 執行 [`supabase/enable-phone-qr-login.sql`](supabase/enable-phone-qr-login.sql)。此檔只新增掃碼登入的暫存表及相關函式。
2. 在 Supabase Edge Functions 的 Secrets 設定 `QR_LOGIN_SITE_URL`（完整正式 HTTPS 網址，含專案目錄及結尾 `/`）與 `QR_LOGIN_OWNER_USER_ID`（和 `src/lib/auth.ts` 的 `OWNER_USER_ID` 相同）。瀏覽器只能使用專案的前端公開金鑰。Edge Function 使用 Supabase 執行環境內建的金鑰，勿將服務金鑰放進前端環境變數。
3. 使用已連結該 Supabase 專案的 CLI 執行 `supabase functions deploy phone-qr-login --no-verify-jwt`，或從 Dashboard 更新該函式的 `index.ts` 並關閉該函式的 Verify JWT，再部署新版網站。手機批准時，Edge Function 會將 Supabase Auth 通行密鑰挑戰綁定此次掃碼請求，並驗證通行密鑰與管理員 UID。
4. 先在 iPhone 註冊管理員通行密鑰。在電腦登入頁點「手機掃碼登入」，再從 iPhone 主畫面打開詮栩 CNC。手機可從登入頁點「掃描電腦登入 QR Code」。已登入的管理員可進入加工管理或庫存管理，打開側邊導覽列，在「設定通行密鑰」下方找到同一入口。掃到自己剛才產生的 QR Code 後，網站會自動請 iPhone 驗證通行密鑰。若手機需要點按或使用者取消系統確認，可按「用 Face ID 確認」重試。驗證成功後，電腦原分頁會自動登入，手機維持原有登入狀態。

電腦和手機都須連網，可使用不同網路。QR Code 僅供站內掃描、有效三分鐘且只可用一次。電腦的兌換憑證只留在發出請求的分頁。關閉或重整電腦掃碼頁後，請重新產生 QR Code。先前已套用掃碼登入 SQL 的環境只需更新 Edge Function 和網站。

## 資料與安全設計

- 匿名角色只能 SELECT 四張業務資料表，沒有 INSERT、UPDATE、DELETE 或業務 RPC 權限。
- 每筆資料的 `user_id` 都必須等於指定 UID；RLS 同時檢查登入 JWT 與資料擁有者。
- 加工紀錄新增與查詢只開放給指定帳號；刪除前由 Supabase Auth 再次驗證帳號密碼。
- 前端可編輯刀具說明欄位，但沒有直接修改 `stock_quantity`、`unit_price` 或歷史資料的權限。
- 所有庫存增減只允許呼叫 `register_stock_movement`。
- 刪除出入庫只允許呼叫已登入帳號專用的 RPC，不能由瀏覽器直接刪除歷史表。
- RPC 從登入 JWT 取得 UID，不接受前端傳入任意 `user_id`。
- 刀具編號會依「刀片、鑽銑刀、刀柄、其他」四種分類分別安全遞增。
- 刪除刀具會一併刪除該刀具的歷史，且必須再次通過帳號密碼驗證。

```text
├─ supabase/enable-product-barcodes.sql # 刀具條碼欄位、唯一性與 Excel 備份升級
├─ supabase/enable-production-product-code-edit.sql # 安全修改加工產品編號並同步歷史紀錄
├─ .env.example
└─ vite.config.ts
```

### 單一 CSS 與個別元件設定

所有樣式都在 `src/styles.css`。檔案依「裝置 → 系統 → 畫面 → 元件」整理，裝置只分成 `621px` 以上電腦版與 `620px` 以下手機版，不另外保留平板版設定。每個功能區內依序放共用、電腦版與手機版規則。

每一行 CSS 程式碼都有繁體中文註解，標示適用裝置、畫面、元件與設定用途。在 VS Code 按 `Ctrl + F` 可直接搜尋「出入庫表格第 9 欄」、「實際數量」或「加工數量登記」。同一行有多個屬性時，註解依原順序說明各項用途。

手機版加工紀錄資料卡的欄名可在 `.production-table:not(.compact) tbody td::before` 的 `font` 設定調整。搜尋「目前使用的加工紀錄手機資料卡各欄位名稱文字」可定位這段樣式。

也可使用下列搜尋關鍵字。

- 搜尋 `「盤點備註」輸入框`，可在同一區看到電腦版完整格式、焦點外框、提示字及手機版完整格式。
- 搜尋 `出入庫紀錄表格` 或 `「備註」欄內容`，可找到出入庫表格及備註欄的欄寬、字級與換行。
- 搜尋 `「查詢最後一筆」按鈕`、`「加工時間（時）」輸入框` 或 `「訂單總數量」輸入框`，可直接找到畫面上的對應元件。

註解不再使用「顯示與操作」、「輸入與結果」、「結果表格」等籠統名稱。例如條碼功能會分別寫成「提示條碼對準位置的黃色掃描框」、「剛掃描到的條碼號碼」、「手動條碼輸入框」；訂單完工預估會分別寫成「訂單總數量輸入框」、「計算方式下拉選單」與「預估完工日期結果卡」。

手機資料卡不再只註解「第 1 欄、第 2 欄」或「欄位與資料列」，而是直接寫成「編號、品名、分類、單價、庫存、實際數量」等實際欄位名稱。

手機版出入庫、庫存盤點與刀具資料卡的欄位標題與內容預設保留 `9px` 間距。需要調整時可在 `src/styles.css` 搜尋各表格的 `.data-table...tbody td::before`，修改其中的 `margin-right`；庫存盤點「實際數量」因標題與輸入框使用 flex 同列排列，請修改該欄的 `gap`。這些數值只影響標題右側留白，不會改變內容字體大小。

庫存盤點的電腦版「實際數量」表頭與輸入框對齊欄位中心，差異顯示在輸入框右側的預留空間。手機版的標題、輸入框、單位與差異同列靠左，「更新」、「備註」與「查看」也一起靠左。輸入區可在 `src/styles.css` 的 `.stocktake-actual` 調整，按鈕尺寸可在 `.stocktake-row-actions > button` 調整。

### 修改三張庫存表格的每一欄

出入庫、庫存盤點與刀具資料三張表格已完全分開。每一欄都有獨立的標題與內容規則，可分別修改 `width`、`font-size`、`color`、`font-weight`、`text-align`。在 `src/styles.css` 搜尋下列完整關鍵字即可找到：

- `電腦版 + 庫存管理系統 + 出入庫表格 + 第 1 欄`。
- `電腦版 + 庫存管理系統 + 庫存盤點表格 + 第 1 欄`。
- `電腦版 + 庫存管理系統 + 刀具資料表格 + 第 1 欄`。

同一欄的 `th` 是欄位標題，`td` 是資料內容。`width` 控制欄寬，同一張表格各欄百分比總和建議維持 `100%`；`font-size` 是字體大小；`color` 是顏色；`font-weight` 是粗細；`text-align: left` 是靠左、`center` 是置中、`right` 是靠右。手機版會改成資料卡排列，請搜尋同一欄位名稱旁的「手機資料卡」設定。

三張表格的共用 `th`／`td` 規則只保留高度、內距、換行等結構設定，不再放 `font-size`、`color`、`font-weight`、`line-height` 或 `text-align`。電腦版與手機版的文字格式都直接寫在各欄的 `nth-child` 中，因此修改某一欄時不會被整張表格的共用文字規則覆蓋。

欄位內的 `.code`、`.quantity`、`.tag`、單位小字、盤點價格及盤點輸入框也會繼承該欄的字體大小與粗細。刀具資料的漲幅已從單價內容拆成緊鄰單價右側的獨立第 8 欄，表頭不顯示文字；漲價顯示紅色、降價顯示綠色、持平顯示 `0%`，沒有前一筆價格時顯示 `—`。品名下方條碼號碼仍保留獨立的小字設定；需要修改時請搜尋 `獨立「漲幅」欄` 或 `品名下方條碼號碼`。

庫存盤點的差異沿用刀具漲幅的顏色，增加顯示紅色正數，減少顯示綠色負數，無差異顯示灰色 0。出入庫的入庫數量顯示綠色、出庫數量顯示紅色。

手機版刀具資料卡的數量與單價排列在同一列；單價的起點與上方分類、供應商對齊。為了避免不同位數的單價與固定漲幅欄產生空隙，手機版會隱藏固定位置的第 8 欄，改將相同漲幅直接放在單價數值後方；電腦版仍維持無標題的獨立漲幅欄。購入日期獨立顯示在下一列，操作按鈕位於日期下方。這段排列可在 `src/styles.css` 搜尋 `手機資料卡的漲幅直接緊接在單價數值右側` 修改。

電腦版與手機版加工數量登記的底部依序是滿寬黃色「送出登記」、紅框暗紅底「刪除最後一筆」及暗黃底「加工時間計算」，三顆按鈕字級皆為 19 px。按鈕樣式可分別找到 `.production-action.save-action`、`.production-action.delete-action` 與 `.production-action.time-tool-action`。沒有最後一筆紀錄時，刪除按鈕會停用並降低透明度。

加工總覽的每個產品日期長條圖在初次載入時會自動捲到最右側，直接顯示最新一筆日期；新增新的加工日期後也會自動移到新的最後一筆。使用者仍可手動向左捲動查看較舊資料，同一日期僅更新數量時不會強制改變使用者目前的捲動位置。

元件的 `font-size`、`font-weight`、寬高、內距、顏色與邊框均直接寫在該元件規則中。庫存表格不再使用 `tbody td * { ... !important }` 強制改寫所有子元件；刀具資料、出入庫及庫存盤點的表格標題與內容也各自在自己的功能區設定，因此個別輸入框或表格設定不會再被另一張表格蓋掉。

修改後可執行 `npm run css:check`。檢查工具會確認單一 `src/styles.css` 沒有同條件重複選擇器、沒有舊平板斷點，且全站字型仍由根目錄變數集中管理。

### 修改網站字型

開啟 `src/styles.css`，在最上方 `:root` 修改 `--font-family-site`，即可統一更換全站一般文字字型；修改 `--font-family-monospace`，即可統一更換編號、數量、金額、統計數字與條碼字型。各功能區只引用這兩個變數，不再各自寫一套字型清單。

搜尋 `--font-feature-slashed-zero` 可控制斜線 0；目前設定為 `"zero" 1`，並在全站搭配 `font-variant-numeric: slashed-zero`。只有字型本身包含斜線 0 字形時才會顯示效果。

手機版的出入庫、庫存盤點與刀具資料卡，編號、日期、數量、單價、金額等數字欄位會明確使用 `--font-family-monospace`，避免被資料卡的一般中文字型覆蓋而看不到斜線 `0`。

`index.html` 已透過 Google Fonts 載入 Noto Sans TC、Roboto Mono 與 JetBrains Mono。若裝置無法連線 Google Fonts，CSS 會依序使用後方列出的系統備用字型。

### 修改網站字體大小

開啟 `src/styles.css`，用畫面名稱搜尋個別元件。每個 `font-size` 都位於實際套用它的元件規則中，不再集中成一大串全站變數。電腦版與手機版會分別標示適用裝置；只需修改同一元件區塊內的數值。

例如盤點備註請搜尋 `「盤點備註」輸入框`；刀具漲跌百分比請搜尋 `漲跌百分比`；條碼請搜尋 `條碼號碼`；出入庫備註請搜尋 `「備註」欄內容`。顏色、字級、粗細、欄寬與換行均在各自區塊調整。

刀具資料品名下方的條碼號碼顏色由 `.product-barcode` 的 `color` 單獨控制，手機版與電腦版共用。共用的 `.data-table small` 小字規則已排除 `.product-barcode`，因此修改條碼專用顏色後不會再被品名欄文字顏色覆蓋；條碼前方掃描圖示的顏色則由 `.product-barcode svg` 分開控制。

登入名稱輸入框允許 Windows 中文輸入法正常進行組字，不會在輸入過程中把文字立即清空；按下登入後仍只接受英文字母與數字，並且必須符合系統設定的登入名稱。手機瀏覽器會優先顯示英文輸入鍵盤。

## 常見問題

### 網站仍顯示「示範模式」

確認兩個環境變數都有正確值，且修改後已重新啟動開發伺服器或重新執行 GitHub Actions。

### 進入庫存管理後顯示資料庫錯誤

通常是還沒完整執行 `supabase/schema.sql`。回到 SQL Editor 重新執行整份檔案，再重新整理網站。

### 出庫顯示庫存不足

這是資料庫交易函式的必要防護。請先確認商品目前庫存，或先登記入庫。

### GitHub Pages 打開後空白

在 Actions 查看 build 是否成功，並確認 Pages 的 Source 是 GitHub Actions。若 workflow 沒有讀到兩個 secrets，網站仍應顯示示範模式，不會因此完全空白。

### iPhone 按「開啟相機掃描」後沒有畫面

確認使用的是 `https://` 正式網址，並到 iPhone 的 Chrome／網站相機權限允許使用相機。若相機暫時無法使用，可先在掃描視窗的「電腦測試／相機無法辨識時」欄位手動輸入條碼，測試查詢、建立與綁定流程。

相機掃描預設使用後鏡頭、1080p、30fps，並在瀏覽器支援時啟用連續對焦與約 1.35 倍變焦。掃描時先讓手機與條碼保持約 20～30 公分，將條碼置於框線中央後再慢慢靠近；避免手機貼得太近或燈光直接反射條碼貼紙。

網站相機掃描會更密集地搜尋 QR Code 的定位圖案，未解碼時等待約 250 毫秒再嘗試，並繼續支援一維條碼。

按「開啟相機掃描」後，手機與電腦都會展開相機預覽及黃色正方形掃描框。預覽高度依螢幕寬度調整，掃描視窗內容可上下捲動。

相機讀到一維條碼或 QR Code 時會播放一聲短促的條碼槍式「嗶」聲，即使該條碼尚未綁定刀具也會播放。iPhone 可用控制中心的音量滑桿調整網頁聲音。若裝置或瀏覽器無法播放，畫面仍會顯示讀到的條碼。

網站會依相機當前的影像尺寸取像。ZXing 讀不到整張畫面時，會依黃色正方形掃描框的位置裁取影像、補上白邊，再用 ZXing-C++（WebAssembly）解讀 QR Code。WebAssembly 隨網站建置提供。掃描刀盒時請讓整張 QR Code 與四周空白都落在黃框內。

### iPhone 連接 XB-6208-RB 後，手機鍵盤不會顯示

這是 iPhone 將藍牙掃描器視為外接鍵盤的正常行為。進入庫存功能的「掃描刀具條碼」視窗，展開「XB-6208-RB：顯示／隱藏 iOS 鍵盤」，再用掃描器掃描畫面中的 QR Code，即可切換手機鍵盤。掃描後若鍵盤沒有立刻出現，請重新點一下要輸入的欄位。這個設定碼只調整掃描器與 iOS 鍵盤，不會變更網站資料。
